# 답변 피드백 · 교정 가이드

답변이 틀렸을 때 이를 기록하고, 원인을 나눠서 고치는 방법입니다.

## 1. 피드백 남기기

모든 질의는 `audit_log`에 기록됩니다(누가·무엇을 물었고·어떤 문서를 인용했는지).
답변이 틀리면 **피드백**을 남깁니다:

```python
from app.db.repositories import FeedbackRepository
fb = FeedbackRepository(session)
fb.record(
    query_text="부장 연봉 밴드는?",
    rating="down",                 # "up"=좋음 / "down"=틀림
    user_id="hong",
    answer_text="...모델 답변...",
    note="정답은 115~150이 아니라 120~160. salary_bands 최신본 반영 안 됨",
    cited_doc_ids=["doc-123"],
)
```

`down` 피드백은 관리자가 처리 대기 목록으로 봅니다:
```python
fb.list_unresolved()      # 미처리 오답 목록
fb.mark_resolved(id)      # 처리 완료 표시
```

> **구현됨:** `feedback` 테이블 + `FeedbackRepository`, 그리고 사용자가 바로 남기는 경로:
> - **질문하기 화면**(Streamlit `질문하기` 페이지): 답변 아래 **👍 정확함 / 👎 틀림 + 메모** 버튼
> - **CLI**(`python -m scripts.ask` 대화형): 답변 후 `!good` 또는 `!bad <무엇이 틀렸는지/정답>`

## 2. 원인별 교정 (틀린 답은 보통 세 가지 이유)

| 원인 | 증상 | 교정 방법 |
|---|---|---|
| **① 원문이 틀림/오래됨** | 인용 문서 자체가 구버전·오류 | 최신 문서를 올려 **새 버전으로 대체**(supersede) → 구버전 검색 제외. (`docs/중복문서_처리.md`) |
| **② 검색이 정답 문서를 못 찾음** | 맞는 문서가 있는데 답변이 근거로 못 씀 | 그 질문→정답문서를 **골드셋(`samples/goldset.json`)에 추가** → `scripts.eval`로 회귀 확인 → 하이브리드(BM25) 추가·리랭커 조정 |
| **③ 근거는 맞는데 생성이 틀림(환각)** | 근거엔 답이 있는데 답변이 왜곡 | 답변 프롬프트 강화(이미 "근거에서만 답" 강제). 반복되면 프롬프트/모델 조정 |

### 원인 구분하는 법

피드백의 `cited_doc_ids`와 답변을 보고:
- 인용 문서에 **정답이 없다** → ② 검색 실패 (또는 ① 원문에 정보 없음)
- 인용 문서에 **정답이 있는데 답이 다르다** → ③ 생성 오류
- 인용 문서가 **틀린/구버전** → ① 원문 문제

## 3. 교정이 재발을 막는 구조 (회귀 방지)

② 케이스는 특히 **골드셋에 추가**하는 게 중요합니다. 한 번 고친 질문이 나중에 다시 틀리지 않도록
`scripts.eval`이 매번 검증합니다(접근통제 회귀 + 검색 품질). 즉 **오답 → 골드셋 → 회귀 테스트**가
품질을 계속 끌어올리는 루프입니다.

## 요약

1. 틀린 답 → `FeedbackRepository.record(...)` 로 기록(👎 + 정답 메모).
2. 원인 분류: **원문 오류 / 검색 실패 / 생성 오류**.
3. 각각: **새 버전으로 대체 / 골드셋 추가 후 검색 튜닝 / 프롬프트 조정**.
4. 골드셋에 넣으면 `scripts.eval`이 재발을 막아줍니다.
