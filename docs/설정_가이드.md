# 설정 가이드 — 한 파일로 메타데이터·거버넌스·권한 관리하기

이 시스템의 **메타데이터 항목, 거버넌스 규칙, 권한(직책·직무)** 은 모두 한 파일에서 관리합니다:

```
config/system.yaml
```

이 파일을 열어 값을 바꾸고 서비스를 재시작하면, **검토 화면(UI)과 검증 규칙이 자동으로 바뀝니다.**
파이썬 코드는 건드리지 않아도 됩니다.

> YAML 문법 팁: 들여쓰기는 **공백 2칸**, 목록은 `- 값`, 주석은 `#`. 탭 문자는 쓰지 마세요.

---

## 1. 메타데이터 항목 (문서에 붙는 분류 정보)

`metadata:` 아래에서 관리합니다.

### 1-1. 문서 유형(doc_types) 추가/삭제

```yaml
metadata:
  doc_types:
    - policy          # 이미 있는 값
    - payroll
    - 복지제도          # ← 이렇게 한 줄 추가하면 UI 드롭다운에 바로 나타남
    # - training      # ← 앞에 #을 붙이거나 줄을 지우면 삭제
```

- **추가**: 목록에 `- 값` 을 한 줄 넣으면 됩니다.
- **삭제**: 그 줄을 지우거나 앞에 `#` 을 붙입니다.
- `unknown` 값은 "AI가 확신 못 함 → 사람 확인 필요"를 뜻하므로 **남겨두는 것을 권장**합니다.

### 1-2. 민감도 등급(sensitivity_levels)

```yaml
  sensitivity_levels:      # 위에서 아래로 갈수록 높은 등급
    - public               # 0 (가장 낮음)
    - internal             # 1
    - confidential         # 2
    - restricted           # 3 (가장 높음)
```

- **순서가 곧 등급**입니다. 사용자의 열람 권한(clearance)과 이 순서를 비교해 접근을 막습니다.
- 등급을 늘리려면 원하는 위치에 한 줄 추가하세요(예: `internal` 위에 `team_only`). 순서를 지켜 편집하세요.

### 1-3. 개인정보 유형(pii_types) / 주제 태그(topics)

```yaml
  pii_types:
    - salary
    - resident_id
    - 지문정보          # 추가 예시
  topics:
    - 연차
    - 급여
    # topics 를 빈 목록([])으로 두면 주제 태그를 자유롭게 입력 가능(검증 안 함)
```

## 2. 거버넌스 항목 (색인 전 필수 확인 항목)

`governance.required_fields:` 에서 **"이 항목을 채워야만 검색에 등록(색인)된다"** 를 정합니다.

```yaml
governance:
  required_fields:
    - sensitivity_level    # 민감도
    - contains_pii         # 개인정보 포함 여부
    - access_groups        # 열람 그룹
    - owner                # 문서 책임자
    # - department         # 이런 식으로 필수 항목을 늘릴 수 있음
```

- 여기 있는 항목이 비어 있으면 검토 화면에서 제출해도 **차단(BLOCKED)** 되고 사유가 표시됩니다.
- 항목을 빼면 그 항목은 선택 사항이 됩니다(예: `owner` 를 지우면 책임자 없이도 색인 가능).

> 지원되는 필수 항목 키: `sensitivity_level`, `contains_pii`, `access_groups`, `owner`.
> 그 외 커스텀 필드를 필수로 만들려면 코드 한 곳(`app/governance/validator.py`) 확장이 필요합니다 — 요청 주세요.

## 3. 권한 관리 (직책 × 직무)

`permissions:` 아래에서 **직책(계급)** 과 **직무(담당 업무)** 를 정의하고, 그 조합이 무엇을 볼 수 있는지 규칙으로 정합니다.

### 3-1. 직책·직무·그룹 정의

```yaml
permissions:
  access_groups:           # 문서에 붙는 라벨이자 사용자에게 부여되는 권한 단위
    - hr_core
    - payroll
    - recruiting
    - evaluation

  positions:               # 직책(계급)
    - 사원
    - 대리
    - 과장
    - 차장
    - 부장

  jobs:                    # 직무(담당 업무)
    - 일반
    - 급여
    - 채용
    - 평가
```

### 3-2. 권한 규칙 (핵심)

각 규칙은 **(직책, 직무) 조합 → 접근그룹 + 최대 열람 민감도(clearance)** 를 정합니다.
한 사용자에게 **매칭되는 모든 규칙의 그룹이 합쳐지고**, clearance는 **그중 가장 높은 등급**이 적용됩니다.
`["*"]` 는 "전체"를 뜻합니다.

```yaml
  rules:
    - name: 인사팀 기본 열람
      positions: ["*"]        # 모든 직책
      jobs: ["*"]             # 모든 직무
      groups: [hr_core]
      clearance: internal

    - name: 급여 담당
      positions: ["*"]
      jobs: [급여]            # 급여 직무면
      groups: [payroll]      # payroll 그룹 부여
      clearance: confidential

    - name: 급여 관리자(차장 이상)
      positions: [차장, 부장]  # 직책이 차장/부장이고
      jobs: [급여]            # 직무가 급여면
      clearance: restricted  # 더 높은 등급까지 열람
```

**이 설계가 회원님 요구를 어떻게 만족하는지:**

| 상황 | 결과 |
|---|---|
| 같은 **급여** 직무, 직책만 다름 | 사원 급여 → clearance `confidential` / 부장 급여 → `restricted` (직책에 따라 다름 ✅) |
| 같은 **부장** 직책, 직무만 다름 | 부장 급여 → `payroll` 그룹 / 부장 채용 → `recruiting` 그룹 (직무에 따라 다름 ✅) |

### 3-3. 사용자 만들기 (직책·직무 지정)

사용자를 만들 때 직책·직무만 지정하면, 위 규칙에 따라 그룹·등급이 **자동 계산**됩니다.

```python
from app.db.repositories import UserRepository
users = UserRepository(session)
users.upsert_user_with_role("hong", position="부장", job="급여", display_name="홍부장")
# → payroll·hr_core 그룹 + clearance restricted 자동 부여
```

규칙(`rules`)을 바꾼 뒤 기존 사용자에 다시 적용하려면 같은 함수를 다시 호출하면 됩니다.

## 4. 항목을 수정하면 UI는 어떻게 되나요?

**대부분 자동으로 바뀝니다. UI 코드를 수정할 필요가 없습니다.**

| 바꾼 것 | UI 반영 | 설명 |
|---|---|---|
| `doc_types`, `sensitivity_levels`, `pii_types` 값 추가/삭제 | ✅ 자동 | 검토 화면 드롭다운/선택지가 즉시 반영(재시작 후) |
| `access_groups` 추가 | ✅ 자동 | "열람 가능 그룹" 선택지에 나타남(단, 그룹이 DB에 존재해야 함 — 사용자 생성 시 자동 등록됨) |
| `required_fields` 변경 | ✅ 자동 | 검증/차단 규칙에 반영 |
| `positions`, `jobs`, `rules` 변경 | ✅ 자동 | 사용자 생성 시 권한 계산에 반영 |
| 필드 라벨(한글 표시 이름) 변경 | ⚠️ 코드 | 화면에 보이는 항목의 **한글 이름**은 UI 파일(`app/review/streamlit_app.py`)에 있음 → 표시명을 바꾸려면 그 파일 수정 |
| 완전히 **새로운 종류의 필드** 추가(예: "계약금액") | ⚠️ 코드 | 스키마·UI 확장 필요 → 요청 주세요 |

정리: **기존 항목의 "값(선택지)"을 늘리고 줄이는 것은 YAML만으로 끝.** 화면에 보이는 항목의 한글 라벨이나
아예 새로운 필드 종류를 추가하는 것은 코드 수정이 필요합니다.

## 5. 편집 후 반영하는 법

```bash
# 1) config/system.yaml 편집 후 저장
# 2) 서비스 재시작 (검토 UI / 스크립트를 다시 실행)
#    - Streamlit: 앱을 멈췄다가 다시 streamlit run ...
#    - 스크립트: 다음 실행부터 반영
```

설정 파일 경로를 바꾸고 싶으면 환경변수로 지정할 수 있습니다:
```bash
export SYSTEM_CONFIG_PATH=/etc/hr-rag/system.yaml
```

---

## 자주 겪는 실수

- **탭 문자 사용**: YAML은 공백만 허용. 에디터에서 탭→공백 설정.
- **들여쓰기 불일치**: 같은 목록의 항목은 들여쓰기를 정확히 맞춰야 함.
- **민감도 순서 뒤바꿈**: `sensitivity_levels` 는 순서가 등급이므로 낮음→높음을 지킬 것.
- **access_groups 오타**: 규칙(`rules`)의 `groups` 값은 위 `access_groups` 목록에 있는 이름과 정확히 같아야 함.
