# 중복·유사 문서 처리 정책

문서를 올릴 때 두 가지 경우가 있습니다: **완전 동일(중복)** 과 **유사(개정판일 가능성)**.

## 1. 완전 동일 문서 (자동 차단) — 구현됨

파일 내용이 바이트 단위로 같으면 `file_hash`(SHA-256)가 일치합니다.
이 경우 **자동으로 차단**되고 기존 문서를 알려줍니다.

- 검토 UI: "이미 등록된 문서입니다(내용 동일). 기존 문서: xxxx" 표시.
- 즉, 같은 파일을 실수로 두 번 올려도 중복 색인되지 않습니다.

구현 위치: `app/ingestion/intake.py`(해시 계산) + `DocumentRepository.hash_lookup`.

## 2. 유사하지만 다른 문서 (개정판 가능성) — 권장 처리 방식

"2025 연차규정.docx" → "2026 연차규정.docx" 처럼 **내용은 비슷하지만 파일은 다른** 경우입니다.
바이트가 다르므로 위 자동 차단에는 걸리지 않습니다.

### 정책: 자동으로 판단하지 않고, 사람에게 물어봅니다

민감한 인사 문서를 시스템이 임의로 "덮어쓰기"하면 위험합니다. 그래서:

1. **적재 시 유사 문서 탐지** → 기존 문서 중 매우 유사한 것이 있으면 검토 화면에 표시:
   > "이 문서는 기존 문서 「2025 연차규정」과 유사합니다(유사도 92%). 어떻게 처리할까요?"
2. **사람이 선택**:
   - **[새 버전]** → 기존 문서를 대체(supersede). 새 문서에 `supersedes=기존ID`, 기존 문서는 `status=superseded`, `superseded_by=새ID`.
     검색은 기본적으로 **최신 버전만 노출**하고 구버전은 자동 제외됩니다.
   - **[별개 문서]** → 둘 다 유지하고 각각 검색됨.

### 버전 관리 메커니즘은 이미 준비돼 있습니다

생애주기 필드(`version`, `supersedes`, `superseded_by`, `status`)가 스키마에 있고,
**검색은 이미 `superseded` 문서를 기본 제외**합니다(`app/search/access.py`의 하드필터).
따라서 "새 버전으로 처리" 를 선택하면 구버전이 자연스럽게 검색에서 빠집니다.

### 유사도 탐지 방법 (도입 시)

| 방법 | 설명 |
|---|---|
| 제목/파일명 정규화 비교 | "2025/2026 연차규정" 처럼 유사 파일명 감지(빠름) |
| 임베딩 유사도 | 문서 대표 벡터의 코사인 유사도가 임계치(예: 0.9) 이상이면 후보 |
| 혼합 | 파일명 + 임베딩 둘 다 보고 후보 제시 |

> **현재 상태(구현됨):**
> - 완전 동일(해시) 차단 ✅
> - **유사 문서 자동 탐지** ✅ (`app/ingestion/dedup.py` — 적재 시 임베딩 유사도로 후보 탐지)
> - **검토 화면에서 "새 버전으로 처리" 선택** ✅ (선택 시 옛 문서 검색 제외)
> - **낮은 유사도 개정판**은 자동 탐지 안 됨 → **문서 관리 화면에서 사람이 수동으로 버전 연결** ✅
>   (Streamlit `문서 관리` 페이지 또는 `DocumentManager.supersede`)

## 3. 이미 쌓여 버린 겹치는 문서 정리 — 폴더 정리 화면

위 2번은 **즉시 처리(검토 화면)** 로 올릴 때만 동작합니다. 예약 업로드·일괄 반입은 검토를
건너뛰므로, 유사 판정은 계산해 두고도 아무도 보지 않은 채 지나갑니다. 여러 사람이 같은
문서를 각자 올린 경우도 마찬가지입니다.

**문서 관리 → `겹치는 문서 정리`** (`/console/cleanup/`) 가 그걸 뒤늦게 보여줍니다.

- **새로 분석하지 않습니다.** 적재할 때 `documents.similar_candidates` 에 저장해 둔 값을
  읽어 묶기만 합니다. LLM 호출 0, 임베딩 0 → 화면이 즉시 뜹니다.
- A↔B, B↔C 면 A·B·C 를 **한 묶음**으로 보여줍니다(따로 뜨면 두 번 정리하게 됩니다).
- 묶음마다 **최신본 후보**(작성일이 가장 늦은 것)를 미리 골라 두지만 **제안일 뿐입니다.**
  라디오로 바꿀 수 있습니다.
- `정리 적용` → 고른 문서만 남고 나머지는 **`대체됨`**. **삭제가 아닙니다.**
  검색에서만 빠지고 원본 파일과 이력은 그대로 남습니다(되돌릴 수 있습니다).
- 각 행의 `내용 보기` 는 다운로드가 아니라 **정보 팝업**입니다(제목·요약·키워드·작성부서).

### 자동으로 정리하지 않는 이유

월간 보고서처럼 **서식이 같고 날짜만 다른 정기 문서**는 내용 유사도가 개정판만큼 높습니다.
자동으로 처리하면 지난 달 보고서가 검색에서 사라집니다. 그래서:

- 날짜를 뗀 제목이 같은데 **날짜가 서로 다르면** `⚠️ 날짜만 다른 정기 문서로 보임` 경고를
  달고 목록 아래로 내립니다.
- 한 묶음이 6건 이상이면 `⚠️ 서식이 같은 문서일 수 있음` 경고를 답니다.

### 권한

- 관리자·부서장(폴더 관리 권한이 있는 사람)만 화면에 들어갈 수 있습니다.
- 묶음에는 **자기가 볼 수 있는 문서만** 들어갑니다(권한 밖 문서는 후보에 있어도 제외).
- `정리 적용` 은 남길 문서·정리할 문서를 **각각 한 건씩 다시 권한 확인**합니다.
- 이미 정리한(`대체됨`) 묶음은 다시 추천하지 않습니다.

## 요약

- **완전 동일** → 자동 차단(구현됨).
- **유사(개정판)** → 시스템이 후보를 제시하고, **사람이 "새 버전 / 별개" 를 선택**. 새 버전이면 구버전은 검색에서 자동 제외.
- **검토를 건너뛴 문서(예약·일괄)** → `겹치는 문서 정리` 화면에서 나중에 사람이 확인.
