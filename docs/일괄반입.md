# 과거 문서 일괄 반입 가이드

보유 중인 과거 문서를 한 번에 적재하는 절차입니다. 웹 업로드가 아니라 **서버에서 명령으로**
실행합니다. 웹으로 수천 건을 올리는 건 시간도 오래 걸리고 중간에 끊기기 쉽습니다.

---

## 0. 핵심 개념 — 폴더가 곧 권한입니다

이 시스템은 **폴더 = 조직 노드 = 작성부서 = 열람 권한 = 저장 경로**로 통합돼 있습니다.
그래서 조직도 모양대로 파일을 정리해 두면 **권한을 한 건씩 지정할 필요가 없습니다.**

```
반입할문서/
  People팀/
    ㅁ그룹/
      ㄴ파트/          ← 이 안의 파일은 'ㄴ파트' 폴더, ㄴ파트 권한으로 등록
        연차규정.docx
      ㅇ파트/
        2024년/        ← 조직도에 없는 하위 폴더는 가장 가까운 상위(ㅇ파트)로 붙음
          평가보고.docx
      그룹공지.docx     ← 파일이 그룹 폴더에 바로 있으면 'ㅁ그룹' 권한
```

폴더 이름은 **조직도에 등록된 이름과 정확히 같아야** 합니다. 손으로 만들면 오타·띄어쓰기
때문에 어긋나기 쉬우니, 아래 1단계에서 **자동으로 만들어 쓰세요.**

---

## 1. 폴더 뼈대 만들기

### 1-1. 조직도부터 완성

웹 → **조직도** 에서 팀 > 그룹 > 파트를 먼저 다 만들어 두세요. 여기 없는 부서는 폴더를
만들어도 매칭되지 않습니다.

### 1-2. 서버에 반입 폴더 생성

**스크립트는 서버에서 도니까 파일도 서버에 있어야 합니다.** 서버에 접속해서:

```bash
python -m scripts.bulk_ingest --dir /srv/반입 --make-dirs
```

조직도 모양 그대로 빈 폴더가 생깁니다:

```
조직도 모양으로 폴더를 만들었습니다: /srv/반입

  + People팀
  + People팀/ㅁ그룹
  + People팀/ㅁ그룹/ㄴ파트
  + People팀/ㅁ그룹/ㅇ파트
  + People팀/ㅅ그룹
```

이제 **이 폴더에 파일만 넣으면 됩니다.** 폴더 이름을 직접 타이핑할 일이 없어집니다.

특정 부서 것만 반입한다면 그 아래만 만들 수도 있습니다:

```bash
python -m scripts.bulk_ingest --dir /srv/반입 --root-node ㅁ그룹 --make-dirs
# → /srv/반입/ㄴ파트, /srv/반입/ㅇ파트 만 생성
```

이미 있는 폴더는 건드리지 않으니 조직이 바뀌면 **다시 실행해서 새 부서 폴더만 추가**하면 됩니다.

---

## 2. 파일 넣기

### 방법 A. 네트워크 공유 (여러 부서가 각자 넣어야 할 때 — 권장)

`/srv/반입` 을 Samba로 공유하면 각 담당자가 **내 PC 탐색기에서 드래그**로 넣을 수 있습니다.
서버에서:

```bash
sudo apt install samba
sudo nano /etc/samba/smb.conf
```

맨 아래에 추가:

```ini
[반입]
   path = /srv/반입
   browseable = yes
   writable = yes
   valid users = @hr반입
```

```bash
sudo groupadd hr반입
sudo smbpasswd -a <사용자계정>        # 담당자마다 실행
sudo usermod -aG hr반입 <사용자계정>
sudo chgrp -R hr반입 /srv/반입
sudo chmod -R 2775 /srv/반입          # 그룹 쓰기 + 새 파일도 그룹 상속
sudo systemctl restart smbd
```

담당자는 윈도우 탐색기 주소창에 `\\서버IP\반입` 을 치고 **자기 부서 폴더에 파일을 끌어다
놓으면 끝**입니다. 조직도 모양이 그대로 보이니 어디 넣을지 헷갈릴 일이 없습니다.

> 부서별로 폴더 권한을 나누고 싶으면 `[반입]` 대신 부서별 공유를 여러 개 만들면 됩니다.
> 다만 반입은 일회성이라 굳이 안 나눠도 됩니다.

### 방법 B. WinSCP / FileZilla (본인 혼자 넣을 때)

1. WinSCP 실행 → 프로토콜 **SFTP**, 서버 IP·계정 입력해 접속
2. 오른쪽(서버) 창에서 `/srv/반입` 으로 이동
3. 왼쪽(내 PC)에서 **폴더째 드래그** — 하위 구조가 그대로 올라갑니다

내 PC에서 미리 같은 구조를 만들어 두고 통째로 올려도 되고, 서버에 이미 만들어진 부서 폴더
안으로 파일만 넣어도 됩니다.

### 방법 C. 이미 파일 서버가 있다면

기존 공유 드라이브를 서버에 마운트해서 그 경로를 `--dir` 로 바로 지정할 수도 있습니다.
다만 폴더 구조가 조직도와 다르면 `--dry-run` 에서 미매칭이 많이 뜰 테니, 복사해 와서
정리하는 편이 안전합니다.

### 파일 넣을 때 주의할 점

| 상황 | 어떻게 되나 |
|---|---|
| 부서 폴더 아래 `2024년/1분기` 같은 하위 폴더 | **그대로 둬도 됩니다.** 가장 가까운 상위 부서(= 그 부서)로 붙습니다 |
| 같은 파일이 두 부서 폴더에 중복 | 내용이 같으면 **먼저 처리된 하나만** 등록됩니다(해시 중복). 두 부서 모두 봐야 하면 상위 부서 폴더에 하나만 두세요 |
| 파일명이 서로 같음(다른 폴더) | 문제 없습니다. 별개 문서로 등록됩니다 |
| `.hwp` 파일 | **등록되지 않습니다.** 목록에서 자동 제외되니 docx/pdf로 변환 후 넣으세요 |
| 압축 파일(zip) | 제외됩니다. 미리 풀어서 넣으세요 |
| 맥에서 올린 한글 파일명 | 자소 분리(NFD)로 보일 수 있습니다. 문제되면 서버에서 `convmv -f utf8 -t utf8 --nfc -r /srv/반입` |

## 3. 매핑 확인 (반드시 먼저)

아무것도 적재하지 않고 "어느 파일이 어느 부서·권한으로 갈지"만 출력합니다.

```bash
python -m scripts.bulk_ingest --dir /path/to/반입할문서 --dry-run
```

출력 예:

```
반입 대상 1,240건 — 폴더(작성부서·열람권한)별 분류

  People팀 / ㅁ그룹 / ㄴ파트: 812건
  People팀 / ㅁ그룹 / ㅇ파트: 401건
  ⚠️ (미분류 폴더): 27건

⚠️  조직도에 없는 폴더에 있는 파일이 27건입니다.
    이대로 실행하면 작성부서 없이(= 팀 전체 공개) 등록됩니다.
```

**`⚠️ (미분류 폴더)` 가 0건이 될 때까지 폴더 이름을 고치세요.** 이 상태로 실행하면 해당
파일들이 **팀 전체 공개**로 들어갑니다. 부서별 결과를 캡처해서 각 부서 담당자에게 확인받으면
좋습니다.

반입 폴더가 조직도 중간부터 시작하면 시작 노드를 지정합니다:

```bash
python -m scripts.bulk_ingest --dir /path/to/ㅁ그룹문서 --root-node ㅁ그룹 --dry-run
```

## 4. 속도 측정 (20건)

전체 소요 시간은 문서 길이와 vLLM 상태에 따라 크게 달라집니다. **추측하지 말고 재세요.**

```bash
python -m scripts.bulk_ingest --dir /path/to/반입할문서 --limit 20 --auto-confirm
```

끝에 `처리 속도: NNN건/시간` 이 나옵니다. 전체 건수 ÷ 이 값 = 예상 시간입니다.

느리면 `--workers` 를 올려서 다시 재보세요. **8 → 16 순으로 올려보고 처리 속도가 더 안 오르는
지점에서 멈추면 됩니다.** vLLM이 요청을 묶어 처리하므로 동시 실행을 늘리면 전체 처리량이
올라갑니다(개별 응답은 느려짐).

---

## 5. 본 실행

```bash
python -m scripts.bulk_ingest \
    --dir /path/to/반입할문서 \
    --auto-confirm \
    --workers 8 \
    --report failed.csv
```

**퇴근 후나 주말에 돌리세요.** 반입 중에는 GPU를 계속 쓰므로 같은 시간대 채팅 응답이 느려집니다.

터미널을 닫아도 계속 돌게 하려면:

```bash
nohup python -m scripts.bulk_ingest --dir ... --auto-confirm > bulk.log 2>&1 &
tail -f bulk.log
```

### 중단해도 됩니다

`Ctrl+C` 로 멈춰도 그때까지 등록된 문서는 그대로 남습니다. **같은 명령을 다시 실행하면 이미
등록된 파일은 건너뛰고 남은 것부터 이어갑니다**(파일 해시로 판별). 부서별로 나눠서 며칠에
걸쳐 돌려도 됩니다.

---

## 6. 실패분 처리

실패한 파일은 `failed.csv` 에 사유와 함께 남습니다.

| 흔한 사유 | 대처 |
|---|---|
| 파일 내용을 읽지 못했습니다 | 스캔 문서인데 OCR이 꺼져 있음 → `.env` 의 `OCR_BACKEND` 확인 |
| vLLM 5xx / 타임아웃 | 일시 장애. 그냥 다시 실행하면 재시도됨 |
| 지원하지 않는 확장자 | `.hwp` 등은 애초에 목록에서 제외됨. 변환 후 반입 |

원인을 고친 뒤 **같은 명령을 다시 실행**하면 성공한 건 건너뛰고 실패분만 재시도합니다.

---

## 7. 반입 후 점검

`--auto-confirm` 은 사람 검토 없이 등록합니다. **권한은 폴더에서 오므로 보안상 위험은 없고**,
AI가 채운 분류·요약만 검증 대상입니다. 전수 확인 대신 **표본 점검**을 권합니다.

1. 웹 → 문서 → 부서 폴더별로 100건쯤 훑어보기
2. 제목·요약·문서 종류가 이상한 게 눈에 띄면 상세 패널에서 바로 수정
3. 채팅에서 대표 질문 10개쯤 던져 답변과 출처가 맞는지 확인

AI가 종류를 정하지 못한 문서는 **기타**로 등록됩니다. 문서 목록에서 종류 `기타`로 필터링해
정리하면 됩니다.

## 옵션 정리

| 옵션 | 설명 |
|---|---|
| `--dir` | 반입할 폴더 (하위 폴더 포함, 필수) |
| `--make-dirs` | 조직도 모양대로 빈 폴더만 만들고 종료 (파일 넣기 전 준비) |
| `--dry-run` | 적재 없이 매핑만 확인 |
| `--root-node` | 반입 폴더가 대응되는 조직 노드(이름 또는 id) |
| `--limit N` | 앞에서 N건만 처리 (속도 측정용) |
| `--auto-confirm` | 검토 없이 즉시 등록. **생략하면 검토 대기로 쌓입니다** |
| `--workers N` | 동시 처리 수 (기본 8) |
| `--ingested-by` | 등록자로 기록할 아이디 (기본 `bulk-ingest`) |
| `--report` | 실패 목록 CSV 경로 (기본 `bulk_ingest_failed.csv`) |

지원 형식: `docx` `pptx` `xlsx` `pdf` `txt` `eml` `jpg` `jpeg` `png`
(숨김 파일, 오피스 임시 파일 `~$*`, `.DS_Store` 등은 자동 제외)

---

## 반입이 끝난 뒤

평상시 물량(하루 수백 건 이하)은 **웹 업로드로 충분합니다.** 한 번에 5~10개씩 끊어 올리면
되고, 이 스크립트를 다시 쓸 일은 없습니다. 나중에 정기 대량 업로드가 부담스러워지면 그때
백그라운드 처리를 얹는 것을 검토하세요.
