# Django 웹앱 실행 가이드

ChatGPT 스타일 채팅(팀 데이터 기반 토글) + 관리 콘솔(문서 검토/관리/사용자 관리).
기존 Streamlit UI는 병행 유지 중이며, Django 검증 완료 후 삭제 예정.

## 1. 설치 & 실행

```bash
pip install -e ".[ingest,web,postgres]"
python web/manage.py migrate                 # Django auth 테이블 생성(기본 sqlite 파일)
python web/manage.py createsuperuser         # 관리자 계정 (username=이메일 권장)
python web/manage.py runserver 0.0.0.0:8500
```

브라우저: `http://서버주소:8500` → 로그인 → 채팅.

- 도메인 데이터(문서·권한·대화)는 기존 `.env`의 **Postgres/Qdrant/vLLM/TEI** 를 그대로 사용.
- 처음이면 `python -m scripts.migrate` 로 도메인 테이블도 갱신하세요(대화 테이블 포함).

## 2. 화면 구성

| 화면 | 경로 | 접근 |
|---|---|---|
| 💬 채팅 | `/` | 로그인한 모든 사용자 |
| 📤 문서 등록 | `/submit/` | 로그인한 모든 사용자 |
| 📝 문서 검토 | `/console/review/` | 관리자만 |
| 📄 문서 관리 | `/console/docs/` | 관리자만 |
| 👤 사용자 관리 | `/console/users/` | 관리자만 |

**관리자 판정**: Django 계정의 `is_staff` 이거나 `config/system.yaml`의 `permissions.admins` 이메일.

## 3. 채팅 사용법

- 입력창 위 **[팀 데이터 기반 답변]** 토글:
  - **켜짐**: 사내 문서에서 근거를 검색해 출처(파일·인용 구절·원본 다운로드)와 함께 답변.
    본인 권한(직책·직무)에 맞는 문서만 검색됩니다.
  - **꺼짐**: 문서 검색 없이 일반 질문(이전 대화 문맥 포함 멀티턴).
- **[과거 문서 포함]** 토글(팀 데이터 기반일 때만): 켜면 **만료·이전 버전(대체된) 문서까지** 검색되고,
  해당 출처에는 **⚠️ 과거/만료 자료** 배지가 붙습니다. 꺼짐(기본)이면 현행 문서만 답변에 사용됩니다.
  과거 포함이어도 **본인 권한(그룹·민감도) 검사는 그대로 적용**됩니다.
- 좌측 대화 목록에서 이전 대화를 이어갈 수 있습니다.
- 답변마다 👍/👎 피드백 → 관리자 검토 대상으로 기록.
- 원본 파일 다운로드는 **다운로드 시점에도 권한을 재검증**합니다.

## 4. 문서 등록·검토 흐름

- **일반 사용자**도 `문서 등록`(`/submit/`)에서 파일을 올릴 수 있습니다 → **검토 대기**에 추가되고,
  관리자가 검토·승인해야 검색에 노출됩니다(등록 즉시 검색되지 않음).
- **관리자**는 `문서 검토`에서 대기 문서의 분류·민감도·열람 권한을 확인·보완한 뒤 색인합니다.

### 4-1. 대량 문서 관리 (수천~수만 건)

`문서 관리`(`/console/docs/`) 화면은 대량을 전제로 설계되어 있습니다:

- **페이징**: 한 페이지 50건씩 로드(전체를 한 번에 불러오지 않아 먹통 방지).
- **필터**: 파일명·제목 검색 + **상태**(사용 중/만료/보관/대체/초안) + **유형** 드롭다운.
- **일괄 작업**: 체크박스로 여러 건 선택 → 한 번에 상태 변경(예: 일괄 보관).
- **🧹 만료 문서 정리**: 만료일이 지난 문서를 즉시 만료 처리(아래 자동화의 수동 실행 버전).

### 4-2. 생애주기 자동화 (만료 자동 처리)

만료일(`expiry_date`)이 지난 문서를 `expired` 상태로 자동 전환하고 검색에서 제외합니다.

```bash
python -m scripts.lifecycle_sweep          # 만료 문서 일괄 정리(배치)
```

cron 등록(매일 새벽 3시) 예시:

```cron
0 3 * * *  cd /path/to/data-gov && python -m scripts.lifecycle_sweep >> /var/log/hrrag_sweep.log 2>&1
```

관리 화면 상단에는 **N일 이내 만료 예정** 건수가 표시되어 갱신 대상을 미리 알 수 있습니다.

## 5. 사용자 등록 흐름

1. 관리자가 `사용자 관리`에서 **ID(이메일)+직책+직무+초기 비밀번호** 입력.
2. 권한(그룹·열람등급)이 `config/system.yaml` 규칙으로 자동 부여되고 **로그인 계정도 함께 생성**.
3. 사용자는 그 이메일/비밀번호로 로그인 → 채팅 사용(본인 권한 적용).

## 6. 서비스 없이 UI 확인 (오프라인 데모)

```bash
WEB_OFFLINE=1 python web/manage.py runserver 0.0.0.0:8500
```

vLLM/TEI/Qdrant/Postgres 없이 in-memory 가짜 컴포넌트로 전체 화면 흐름을 볼 수 있습니다.
자동 검증: `python -m scripts.web_smoke`

## 7. 운영 참고

- Django auth DB를 Postgres로 쓰려면: `DJANGO_DB=postgres` (기존 DB에 django_* 테이블 추가).
- 운영 필수 env: `DJANGO_SECRET_KEY`(랜덤 문자열), `DJANGO_DEBUG=0`, `DJANGO_ALLOWED_HOSTS=사내주소`.
- 만료 문서 자동 정리(`scripts.lifecycle_sweep`)를 **cron 에 등록**하세요(위 4-2 참고).
- 대량(수만 건) 문서에서 문서 관리 화면이 느리면, 기존 DB에 인덱스가 없을 수 있습니다.
  신규 배포는 자동 생성되며, 기존 DB는 `documents(lifecycle_status, doc_type, expiry_date, updated_at)`에
  인덱스를 추가하면 됩니다.
- 사내 SSO(OIDC)는 `mozilla-django-oidc` 패키지로 연동 가능(추후 요청 시 구성).
