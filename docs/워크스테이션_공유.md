# 워크스테이션 공유 — 팀원이 자기 서비스를 만들 때

팀원들이 같은 서버에서 **자기들만의 서비스**를 만들면서 PostgreSQL·Qdrant 가 필요한
경우입니다. 이미 떠 있는 걸 같이 쓰면 될 것 같지만, **둘의 사정이 다릅니다.**

---

## 결론 요약

| | 같이 써도 되나 | 이유 |
|---|---|---|
| **PostgreSQL** | ✅ **된다** | 한 서버가 데이터베이스를 여러 개 담을 수 있고, **계정별로 접근을 막을 수 있다** |
| **Qdrant** | ❌ **안 된다** | **컬렉션 단위 권한이 없다.** 붙기만 하면 인사 문서 전문을 다 읽을 수 있다 |
| **GPU (vLLM/TEI)** | ⚠️ 조건부 | VRAM 상한을 정해 나눠 쓰면 가능. 안 정하면 서로 죽인다 |
| **디스크** | ⚠️ 조건부 | 800GB 를 나눠 쓰는 것이니 쿼터·모니터링 필요 |

---

## 1. PostgreSQL — 같이 써도 됩니다

### 개념

PostgreSQL 서버 하나 = 아파트 한 동입니다. 그 안에 **데이터베이스(집)** 를 여러 개
만들 수 있고, **계정(열쇠)** 마다 들어갈 수 있는 집을 정할 수 있습니다.

```
PostgreSQL 서버 (포트 5432)
├── ragdb        ← 인사 RAG 용 (ragadmin 만 접근)
├── teamapp_db   ← 팀원 A 서비스 (teamapp 만 접근)
└── analytics_db ← 팀원 B 서비스 (analytics 만 접근)
```

### 만들어 주는 방법

서버에서 관리자 계정으로 접속합니다.

```bash
docker compose exec postgres psql -U ragadmin -d postgres
```

`psql=#` 프롬프트가 뜨면 아래를 실행합니다(팀원 하나당 한 벌).

```sql
-- 1) 팀원용 계정과 데이터베이스를 만든다
CREATE USER teamapp WITH PASSWORD '팀원에게-줄-비밀번호';
CREATE DATABASE teamapp_db OWNER teamapp;

-- 2) 남의 데이터베이스에는 아예 못 붙게 한다  ← 이 줄이 핵심
REVOKE CONNECT ON DATABASE ragdb FROM PUBLIC;
REVOKE CONNECT ON DATABASE teamapp_db FROM PUBLIC;
GRANT  CONNECT ON DATABASE teamapp_db TO teamapp;
```

**2번을 빠뜨리면 안 됩니다.** PostgreSQL 은 기본적으로 *모든 계정이 모든 데이터베이스에
접속*할 수 있게 돼 있습니다(`CONNECT` 가 `PUBLIC` 에 기본 부여). 테이블 내용까지 바로
읽히지는 않지만(테이블 권한은 별도), 문을 아예 잠가 두는 게 맞습니다.

확인:

```sql
\l                     -- 데이터베이스 목록과 권한
\du                    -- 계정 목록
```

빠져나오기: `\q`

### 팀원에게 줄 접속 정보

```
호스트   : localhost   (같은 서버에서 돌리면)
포트     : 5432
DB 이름  : teamapp_db
사용자   : teamapp
비밀번호 : (위에서 정한 값)
```

파이썬이면 이렇게 씁니다.

```python
DATABASE_URL = "postgresql://teamapp:비밀번호@localhost:5432/teamapp_db"
```

### 절대 하면 안 되는 것

- **`ragadmin` 계정을 공유하지 마세요.** 이 계정은 인사 데이터베이스의 주인이라
  모든 걸 읽고 지울 수 있습니다.
- 팀원이 `ragdb` 에 테이블을 만들게 하지 마세요. 우리 마이그레이션과 충돌합니다.

## 2. Qdrant — 같이 쓰면 안 됩니다

### 왜 안 되는지 (직접 확인했습니다)

Qdrant 는 **컬렉션별 권한이라는 개념이 없습니다.** 포트에 붙을 수만 있으면 모든 컬렉션을
읽고 쓰고 지울 수 있습니다. 그리고 우리 시스템은 **문서 본문 텍스트를 payload 에 그대로
저장**합니다(검색 결과에 원문을 보여줘야 하므로).

권한을 전혀 모르는 제3자가 `scroll` 한 번 하면 이렇게 나옵니다.

```python
pts, _ = client.scroll(collection_name="hr_chunks", limit=10, with_payload=True)
```

```
{'text': '연차 휴가는 15일이며 인사팀에 신청한다. 급여는 매월 25일 지급.',
 'parent_doc_id': 'D1', 'access_groups': ['n:5'], 'source_filename': '급여규정.docx'}
```

**우리가 만든 조직도 기반 권한 통제가 통째로 무력화됩니다.** `access_groups` 는 우리
애플리케이션이 검색할 때 스스로 지키는 약속일 뿐, Qdrant 가 강제해 주는 게 아닙니다.
팀원이 악의가 없어도 실수로 `delete_collection("hr_chunks")` 한 번이면 색인이 날아갑니다.

> Qdrant 오픈소스에 인증이 아예 없는 건 아닙니다. 다만 **인스턴스 전체에 하나짜리
> API 키**(+읽기전용 키)뿐이라 "이 팀은 이 컬렉션만" 같은 구분이 안 됩니다.

### 해결 — 팀원용 Qdrant 를 따로 띄웁니다

Qdrant 는 가볍기 때문에 하나 더 띄우는 게 정답입니다. 포트와 저장 공간만 다르게 줍니다.

팀원이 자기 폴더에 `docker-compose.yml` 을 이렇게 만들면 됩니다.

```yaml
services:
  qdrant:
    image: qdrant/qdrant:latest
    restart: unless-stopped
    ports:
      - "127.0.0.1:6335:6333"      # 우리는 6333, 팀원은 6335
    volumes:
      - qdrantdata_team:/qdrant/storage

volumes:
  qdrantdata_team:
```

```bash
docker compose up -d
```

팀원 코드에서는 `QdrantClient(url="http://localhost:6335")` 로 붙습니다.
**서로 완전히 분리되어** 실수로 남의 컬렉션을 건드릴 수 없습니다.

### 우리 쪽도 잠가 두세요

지금 `docker-compose.yml` 은 Qdrant 를 모든 네트워크에 열어 두고 있습니다. 같은 서버에
여러 사람이 로그인해 쓰는 상황이면 더 위험합니다. **API 키**를 걸어 두는 것을 권합니다.

```yaml
  qdrant:
    ports:
      - "127.0.0.1:6333:6333"          # 서버 안에서만
    environment:
      QDRANT__SERVICE__API_KEY: ${QDRANT_API_KEY}
```

`.env` 에 키를 넣고, 우리 코드도 그 키로 붙게 해야 합니다. `QdrantIndexer` 가
`QdrantClient(host=..., port=...)` 로 붙고 있으니 `api_key=settings.qdrant_api_key` 한
줄을 더하고 설정 항목을 추가하면 됩니다(클라이언트가 `api_key` 인자를 지원하는 것은
확인했습니다). **적용을 원하시면 말씀 주세요 — 코드 변경이 필요합니다.**

## 3. GPU — 나눠 쓰려면 상한을 정해야 합니다

이 워크스테이션은 RTX 6000(96GB) 한 장이고, **MIG(하드웨어 분할)를 지원하지 않습니다.**
즉 물리적으로 칸막이를 칠 수 없고, 각자 "나는 몇 GB 까지만 쓰겠다"고 **양보하는 방식**
으로만 나눠 쓸 수 있습니다.

현재 배치(`docs/vram.md`):

| 용도 | VRAM |
|---|---|
| vLLM (Qwen3.6-27B) | ~70GB |
| 임베딩 + 리랭커 (TEI) | ~6GB |
| **남는 것** | **~20GB** |

팀원이 자기 모델을 띄우려면 이 ~20GB 안에서 써야 합니다. **상한을 안 정하면** 파이토치나
vLLM 은 기본적으로 GPU 메모리를 최대한 선점하려 들기 때문에, 먼저 뜬 쪽이 다 먹거나
나중에 뜬 쪽이 OOM 으로 죽습니다. **인사 RAG 채팅이 갑자기 안 되는 사고**가 이렇게
납니다.

팀원에게 이렇게 안내하세요.

```python
# 파이토치를 직접 쓰는 경우 — 이 프로세스가 쓸 수 있는 GPU 비율을 제한
import torch
torch.cuda.set_per_process_memory_fraction(0.2)     # 96GB 중 약 19GB
```

(이 샌드박스에는 GPU·torch 가 없어 위 두 명령은 실행 검증을 못 했습니다. 수치는
`docs/vram.md` 의 현재 배치 기준입니다.)

```bash
# vLLM 을 띄우는 경우
vllm serve <모델> --gpu-memory-utilization 0.2 --port 8010
```

지금 누가 얼마나 쓰는지 확인:

```bash
nvidia-smi
watch -n 2 nvidia-smi        # 2초마다 갱신
```

> **더 나은 방법**: 팀원이 LLM 이 필요한 것뿐이라면, 새로 띄우지 말고 **이미 떠 있는
> vLLM 을 API 로 같이 쓰는 것**이 훨씬 낫습니다. vLLM 은 여러 요청을 묶어 처리하도록
> 만들어져 있어서, 모델을 하나 더 올리는 것보다 자원 효율이 비교가 안 됩니다.
> `http://localhost:8000/v1` 로 OpenAI 호환 API 를 그대로 쓸 수 있습니다.

## 4. 디스크 — 서로 침범하지 않게

800GB 를 나눠 쓰는 것이므로, 한쪽이 다 채우면 **다른 쪽도 같이 죽습니다.** 도커 볼륨이
꽉 차면 PostgreSQL 은 쓰기를 멈추고, 그 순간 문서 등록이 전부 실패합니다.

```bash
df -h /                          # 전체 남은 용량
docker system df                 # 도커가 쓰는 용량
du -sh storage/originals         # 우리 원본 파일
```

- 팀원 작업 폴더는 각자 홈 디렉터리(`/home/이름`)에 두게 하세요.
- 도커 이미지가 쌓이면 꽤 먹습니다. 가끔 정리: `docker image prune -a`
  (⚠️ **`docker system prune -a --volumes` 는 볼륨까지 지웁니다. 쓰지 마세요.**)
- 여유가 20% 아래로 떨어지면 경고하도록 알림을 걸어 두면 좋습니다.

## 5. 계정 — 서버 로그인 자체를 나누세요

지금처럼 모두가 같은 리눅스 계정으로 로그인하면, 누가 무엇을 했는지 알 수 없고
실수로 남의 파일을 지울 수 있습니다.

```bash
sudo adduser teammate1                    # 팀원 계정 생성
sudo usermod -aG docker teammate1         # 도커 명령 사용 허용
```

> ⚠️ `docker` 그룹에 넣으면 사실상 **서버 관리자 권한**을 주는 것과 같습니다
> (도커로 아무 파일이나 마운트해 읽을 수 있음). 믿을 수 있는 팀원에게만 주고,
> **우리 프로젝트 폴더는 권한을 잠가 두세요.**

```bash
sudo chown -R $USER:$USER /opt/data-gov
chmod -R o-rwx /opt/data-gov              # 남들은 아예 못 읽게
```

특히 `.env` 에는 DB 비밀번호가 들어 있습니다.

```bash
chmod 600 /opt/data-gov/.env
```

> **PostgreSQL** — 같이 씁니다. 아래 정보로 붙으세요.
> ```
> postgresql://teamapp:비밀번호@localhost:5432/teamapp_db
> ```
> `ragdb` 는 인사 데이터라 접근이 막혀 있습니다.
>
> **Qdrant** — 따로 띄우세요. 6333 은 인사 시스템 전용입니다.
> 위 3-2 의 compose 파일로 6335 에 본인 것을 띄우면 됩니다.
>
> **LLM** — 새로 띄우지 말고 `http://localhost:8000/v1` 을 그대로 쓰세요.

>
> **GPU 를 꼭 직접 써야 한다면** — 반드시 상한을 걸어 주세요(전체의 20% 이내).
> 안 그러면 인사 RAG 채팅이 멈춥니다.
>
> **작업 폴더** — 각자 홈 디렉터리에 두세요.

## 부록: 왜 Qdrant 만 다른가

한 문장으로 정리하면 이렇습니다.

> **PostgreSQL 은 "누가 무엇을 볼 수 있는지"를 DB 자신이 강제한다.
> Qdrant 는 그 개념이 없어서, 붙을 수 있으면 전부 볼 수 있다.**

그래서 PostgreSQL 은 계정을 나눠 같이 쓰면 되고, Qdrant 는 인스턴스를 나눠야 합니다.
