인사팀 온프레미스 문서 RAG 시스템 구축 보고

사내 인사팀 문서(규정·지침·양식·명단 등)를 한곳에 적재하고, 자연어 질문으로 근거와 함께 답변받는 완전 폐쇄망(온프레미스) 시스템입니다. 외부 API 호출이 없으며, 문서 열람 권한은 조직도를 그대로 따릅니다.

1. 왜 만들었나

  • 인사 문서가 개인 PC·공유 드라이브에 흩어져 있어 어떤 문서가 최신인지 확인이 어려움
  • 같은 질문이 반복 문의되고, 답변자마다 근거 문서가 달라짐
  • 민감 문서가 많아 외부 SaaS 사용 불가 → 사내 GPU 서버에서만 동작해야 함

2. 전체 구조

계층구성역할
화면Django채팅, 문서 관리, 조직도/사용자 관리 (얇은 웹 계층)
도메인Python + SQLAlchemy적재 파이프라인, 거버넌스 검증, 권한 계산 (화면 비의존)
생성 LLMvLLM (Qwen3.6-27B)메타데이터 자동 채움, 답변 생성, 표 질의 SQL 생성
임베딩/리랭커TEI (KURE-v1 / bge-reranker-v2-m3)한국어 특화 벡터화 및 재순위
벡터 검색Qdrantdense + BM25 하이브리드 검색, 권한·상태 하드필터
메타데이터PostgreSQL문서·사용자·조직도·감사로그
표 데이터DuckDB대용량 엑셀을 표(테이블)로 적재해 집계 질의 처리

질의 처리 흐름: 질문 → 하이브리드 검색(dense+BM25, RRF 융합) → 권한 재검증 → 리랭킹 → 근거 강제 프롬프트로 답변 생성 → 출처 문서 인용. 근거가 없으면 지어내지 않고 "확인할 수 없습니다"로 답합니다.

3. 주요 기능

3-1. 문서 등록 — AI 자동 채움 + 등록자 검토

  • 파일을 올리면 파서(docx/pptx/xlsx/pdf/이미지/txt)가 본문을 추출하고, LLM이 메타데이터를 자동으로 채움 (문서 종류, 제목, 요약, 핵심 키워드, 예상 Q&A, 유관 조직, 작성일/유효일 등)
  • 자동 채움 결과를 올린 사람이 직접 확인·수정한 뒤 "등록 확정" → 그때 검색에 노출 (human-in-the-loop)
  • 필수 항목(요약·키워드 등)이 비면 적재를 차단 — 품질 낮은 문서가 검색을 오염시키지 않도록
  • 여러 파일 동시 업로드, 업로드 진행 표시, 취소 지원. 두 번째 파일부터는 직전에 확정한 문서 설정을 기본값으로 승계
  • 제목이 부적절한 파일명이면 AI가 제목을 정규화하고, 날짜는 (YY-MMDD) 형식으로 앞에 통일
  • 동일 파일 재업로드는 해시로 중복 탐지, 같은 제목+형식이면 이전 버전 교체 / 삭제 요청 / 별개 등록 중 선택

3-2. 조직도 = 폴더 = 권한 (하나의 개념으로 통합)

  • 조직도(팀 > 그룹 > 파트)를 화면에서 직접 만들고, 사용자는 여러 부서에 동시 소속 가능. 부서장은 조직도에서 지정
  • 업로드 시 고른 폴더가 곧 작성부서이자 서버 저장 경로 — 디스크에도 조직도와 똑같은 폴더 구조로 저장됨
  • 부서 이름을 바꾸면 실제 디렉터리·저장 경로도 함께 정리되고, 문서가 남아 있는 부서는 삭제가 차단됨
  • 열람 권한은 폴더(부서) 선택 하나로 결정: 선택한 부서와 그 하위 조직 전원 + 상위 부서장이 열람. 아무것도 안 고르면 팀 전체 공개
  • 권한은 화면뿐 아니라 검색 단계에서 하드필터로 적용 — 권한 없는 문서는 검색 결과·인용에 아예 등장하지 않음

3-3. 문서 관리 화면

  • 왼쪽 폴더 트리(부서별 문서 수) · 가운데 목록 · 오른쪽 상세/수정 패널의 3분할 구성
  • 목록에서 제목·문서 종류·작성일·작성자·상태 확인, 검색·필터, 여러 문서 일괄 삭제
  • 상세 패널에서 메타데이터 수정, 폴더(작성부서) 이동, 관련 문서 추가, 원본 다운로드
  • 사람·문서 지정은 드롭다운이 아니라 검색형 선택(동명이인은 이름+ID로 구분)

3-4. 문서 생애주기와 버전

  • 상태는 유효 / 만료 / 보관 3가지. 검색에는 유효 + 보관이 노출되고, 만료·이전버전은 기본 제외
  • 새 문서 등록 시 "이 문서가 대체할 옛 문서"를 지정하면 그 문서는 이전 버전으로 내려가 검색에서 빠짐 (AI가 이전 버전 후보를 먼저 추천)
  • 문서 간 관련 문서 연결(최대 3개)을 AI가 자동 추천하고, 등록자가 확정

3-5. 표(엑셀) 데이터 처리

수만 행짜리 명단·급여 파일을 통째로 벡터화하면 검색 품질이 무너지므로 2단계로 나눴습니다.

  • Tier 1 — 큰 시트는 본문 대신 스키마 카드(컬럼 목록·행 수·샘플 몇 줄)만 색인. "그런 자료가 어디 있는지"는 검색으로 찾을 수 있게 함
  • Tier 2 — 같은 파일을 DuckDB 테이블로 구조화 적재. 집계·조건 질문이 들어오면 LLM이 SQL을 생성해 실제로 계산한 뒤 답변
  • SQL은 단일 SELECT만 허용, 등록된 테이블만 조회, DML/CTE 금지, LIMIT 자동 주입으로 안전장치 적용

3-6. 채팅(질의응답)

  • 질문 → 답변 + 출처 문서 인용. 표 질의는 계산 결과를 카드로 함께 표시
  • 폴더 범위를 지정해 검색 가능(상위 폴더 선택 시 하위 포함)
  • 답변마다 정확해요 / 틀렸어요 피드백 수집

3-7. 관리·거버넌스

  • 사용자 등록·수정·삭제, 부서 배정, 부서장 지정
  • 본인 부서 문서는 수정 가능, 삭제는 부서장. 타 부서 문서는 수정/삭제 요청 → 부서장 승인
  • 모든 질의·적재·권한 판정은 감사로그로 기록

4. 권한 요약

대상가능한 작업
일반 구성원권한 범위 내 문서 검색·열람, 문서 등록, 본인 부서 문서 수정, 타 부서 문서는 수정/삭제 요청
부서장위 전부 + 자기 부서 문서 직접 삭제, 수정/삭제 요청 승인
관리자조직도·사용자 관리, 전체 문서 관리

문서 열람 범위: 선택 부서 + 하위 조직 전원 + 상위 부서장. 미선택 시 팀 전체 공개.

5. 품질 검증

  • 단위/통합 테스트 144건 전량 통과 (권한 계산, 폴더 저장·이동, 제목/날짜 정규화, 엑셀 파서, DuckDB 질의 등)
  • 웹 스모크 테스트: 로그인 → 업로드 → 검토·확정 → 폴더별 검색 → 수정 → 삭제까지 전 화면 자동 점검
  • 검색 품질 평가: 골드셋 기반 Recall@k / MRR / nDCG@k, LLM-as-judge(근거성·관련성)
  • 접근통제 회귀 테스트: 권한 없는 문서가 답변에 인용되면 테스트 실패 처리
  • 서비스 없이 동작을 시연하는 오프라인 데모 모드 제공

6. 현재 상태 / 다음 단계

  • 구축 완료 — 기능 구현, 테스트, 화면 정비까지 끝난 상태로 사내 시범 운영 가능
  • 다음 단계 제안
    • 인사팀 실제 문서로 파일럿 적재 후 답변 품질 측정(골드셋 확장)
    • 사용자 피드백(틀렸어요) 기반 검색 파라미터·프롬프트 튜닝
    • 대상 부서 확대 및 정기 문서 갱신 절차(매월 명단 업로드 등) 정착

7. 서버 적용 절차

  1. 최신 코드 받기 (git pull)
  2. 추가 라이브러리 설치 (표 데이터 기능용: duckdb, sqlglot)
  3. DB 스키마 마이그레이션 실행
  4. 기존 색인 문서에 폴더 정보 백필 스크립트 1회 실행 (폴더 범위 검색이 기존 문서에도 적용되도록)
